# Easy summary（中文对照）

本文件是 [`SKILL.md`](SKILL.md) 的中文对照，供人阅读，运行时不起作用。

总结是一份**简报**：写给不在场、而且会把它转述出去的人。审计给这一轮下判断，总结把这一轮讲清楚。

差别一句话就能试出来：文档里一出现"应该修""必须做"或者验收条件，它就是审计了，改用 `easy-audit`。

写之前先读 [references/readability-law.md](references/readability-law.md)，十二条在这里全部适用。

## 取舍规则

一条变化只有当它**会改变读者的预期或动作**时才留下。其余都是例行公事，例行公事一行带过。

这条规则就是全部的活。被要求"总结一下"时，agent 的默认行为是按发生顺序把所有事列一遍；简报只列少数几件
要紧的，并说出它们意味着什么。

## 输出

开写前问一次：**Markdown，还是单文件 HTML 报告？** 用户不表态就默认 Markdown。

要报告，就先把 Markdown 写完，然后调用 Skill 工具并传入 "easy-report"。模板与填写规范由它拥有，事实由它
保持一致。

## 流程

五步。每步结束在一个你能验证的判据上。

### 1. 锁定窗口与基线

窗口是覆盖的时段。基线是读者拿来比较的东西：上次总结、计划、发布、或者说"这一轮之前"。缺哪个问哪个，
只问缺的那个。

**完成判据**：头部同时出现两者 —— 一个日期区间，一个点名的基线。

### 2. 收集变化

来源：窗口内的 `git log`、上次审计留下的计划、已关闭的 ticket、用户的记录。**被砍掉或推迟的工作也要收**，
它同样改变预期。

**完成判据**：每条候选变化都点名了来源。

### 3. 取舍

对每条候选套用取舍规则，留下少数几条。一条读者本来就会预期的变化，不值得占位。

**完成判据**：留下的每一行都写了它对读者意味着什么；例行公事压成表尾一行。

### 4. 写三段

第三部分写的是现状，不是交办。每一行点出一件还没做完的事，以及它没做完对读者意味着什么。说完就停：
要不要把它变成活，是读者决定。

两到三句把变化串起来：方向、解开了什么、代价是什么。这是会被读者转述的一段，所以它承载的是一个判断，
不是一张清单。

- 设备令牌端点，推送才够得着真机。
- 旧轮询还在随包发出，在它下线之前有两条路在读消息。

**完成判据**：三段都在；第一部分一屏装得下；第三部分陈述现状，不下指令。

### 5. 自检

跑 [references/readability-law.md](references/readability-law.md) 的编辑流程，再查三条：

- 只读第一部分的人，能复述出变化和它的含义。
- 没有严重度用词、没有 owner、没有验收条件。那些属于审计。
- 表里每一行的"意味着什么"列都有内容。

## 变化用词

两套，声明一次，只用在这张表里。

| 类型 | 用在 |
|---|---|
| **新增** | 以前不存在。 |
| **变更** | 读者已知的行为，现在不一样了。 |
| **修复** | 原来是坏的，现在不坏了。 |
| **移除** | 没有了。 |

| 状态 | 用在 |
|---|---|
| **完成** | 做完并验证过。 |
| **进行中** | 开始了，没结束。 |
| **未开始** | 排了，没动。 |

共七个词，不许同义词，不许中途发明第八个。文档不用英语时，把它们翻译一次，然后全篇只用那一版。

## 语言

文档用用户正在用的语言写。

## 加粗与换行

加粗标的是标签或主干判断，句子保持朴素。只有三处挣得到：

- 第一部分开头的结论行
- 表里状态为**进行中**的变化 ID
- 用到字段的地方，行首的字段名

其余全部朴素：其他单元格、所有表头、所有完整句子。上限见可读性法条第 5 条。

换行换在读者眼睛需要重新起步的地方：

- 一个字段一行
- 每张表和每个标题前后各空一行
- 一行一条变化；需要两行的变化其实是两条
- 段落至多 3 句，源文件每行至多 120 字符

## 反模式

- 按时间顺序倾倒。这是默认输出，也是这个 skill 要替换掉的东西。
- 列出了每一条变化，却没有含义那一层。
- 严重度用词、owner、验收条件。那些属于审计。
- 总结跟它所总结的工作一样长。
- 第三部分下指令。总结报告什么还开着。
- 百分比没有分母。数字要留，就说清它是占什么的比。
